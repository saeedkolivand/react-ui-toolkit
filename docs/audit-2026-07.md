### Removed as unused

- `@types/classnames` — deprecated stub; npm's own message is _"classnames provides its own type
  definitions"_
- `@tailwindcss/cli` — a build CLI sitting in `dependencies`, referenced by no script
- `ts-jest` — the transform is `babel-jest`
- `@storybook/mdx2-csf` — Storybook 6 era
- `@mdx-js/loader`, `@mdx-js/react` — no `.mdx` files exist
- `gh-pages` — CI deploys now
- `scripts/release.js` — 86 lines, replaced by semantic-release
- `src/pages/index.tsx` — unexported kitchen-sink page that only cost typecheck time; its markup
  became the landing page gallery
- `vite-tsconfig-paths` — was installed and unused. Briefly used for Storybook's `@/*` alias, then
  dropped: it bundles `tsconfck`, which peers `typescript ^5` and therefore forced a **second,
  nested TypeScript 5.9.3** into the tree alongside 6.0.3. `.storybook/main.ts` sets the alias
  directly with `fileURLToPath(new URL(...))` instead.
- `eslint-plugin-react` — no release supports ESLint 10; it calls `context.getFilename()`, removed
  in v10. Replaced by `@eslint-react/eslint-plugin`.

### Security

`npm audit` went from **28 vulnerabilities (2 critical, 17 high)** to what remains below.

### Dark mode never applied the `dark` class — fixed

`README.md` advertised _"Dark Mode — Built-in dark mode support"_ and `tailwind.config.mjs` set
`darkMode: "class"`, but `ThemeProvider` (`src/context/ThemeContext.tsx`) only held a `useState`
value — **it never added the `dark` class to the DOM**. `ThemeToggle` flipped a boolean nothing
rendered from.

Scale of the dead code: **219 `dark:` utilities across 22 component files**, compiling to **79
`.dark` rules in `dist/styles.css`** that no selector could ever match.

The provider now applies the class in an effect, persists the choice to `localStorage`, and falls
back to `prefers-color-scheme` when nothing is stored. Covered by
`src/context/ThemeContext.test.tsx`; removing the one `classList` line fails 5 of its 7 tests.

## Open — found, not changed

### React 19-only, strict lint — done

The repo now lints strict: no rule is disabled to hide a real finding, and every React Compiler rule
from `eslint-plugin-react-hooks` runs at its stock severity. `peerDependencies` moved to
`react ^19.0.0`, which is what made that possible.

What it took:

- `forwardRef` removed from 10 components; `ref` is a normal prop. `Switch` accepted a ref and then
  **dropped it on the floor** (`_ref` was never attached) — `<Switch ref={...}>` had never worked.
- `<Context.Provider>` → `<Context>`, `useContext` → `use` in ThemeProvider and NotificationProvider.
- The `mounted`-flag portals in `Tooltip` and `NotificationProvider` now gate on a new
  `useIsHydrated()` (`useSyncExternalStore`), which is SSR-safe without the cascading re-render, and
  lets `Tooltip` stop reading its portal container from a ref during render.
- `Tabs` syncs `defaultActiveTab` during render instead of in an effect, per the React docs.
- Dead code removed: `Select` computed a whole unused `buttonClasses` block and tracked an
  `isFocused` state nothing read (so its focus/blur handlers had no effect); `Table` destructured a
  `loading` prop it never rendered; `Tooltip` accepted a `className` it never applied.

Lint went 49 warnings → 28, **0 errors**. 24 of the remaining 28 are `any` in test mocks.

## Open — found, not changed

### 1. TypeScript is on 6.0.3, not 7.0.2

TypeScript 7 (the native port) is `latest`, but `@typescript-eslint/parser@8.65.0` declares
`typescript ">=4.8.4 <6.1.0"` and no typescript-eslint release supports 7 yet. Pinned `~6.0.3`
(tilde, not caret — `6.1.0` would re-break that peer). Revisit when typescript-eslint ships TS 7
support.

### 2. 27 remaining `npm audit` advisories, all dev-only and unfixable upstream

Down from 28 (2 critical, 17 high) before the upgrade. All 27 trace to just **two** transitive
packages inside the dev toolchain's own dependency trees:

- `brace-expansion` ≤5.0.7 (high) — reached via the `minimatch` vendored inside eslint and jest
- `tar` ≤7.5.20 (moderate) — reached via semantic-release

Neither reaches the published package: `dependencies` is only `classnames`, `framer-motion` and
`tailwind-merge`.

Overriding `brace-expansion` to `^5.0.9` **was tried and reverted**: v5 changed its export shape, so
the vendored `minimatch` inside eslint threw `TypeError: expand is not a function` and the linter
stopped running entirely. Wait for eslint/jest to bump their own pins.

### 3. The `commit-msg` hook does too much

`.husky/commit-msg` runs commitlint **plus** typecheck, `lint:fix`, lint-staged and the full Jest
suite, so every commit pays the whole CI cost. Conventionally commitlint belongs in `commit-msg` and
the rest in `pre-commit` (or only in CI, which now covers all of it). Left alone — it works, and
splitting it is a workflow preference.
